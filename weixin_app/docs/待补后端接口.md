# 青云 2.0（V4）待补后端接口清单

> 基准：`qingyun-app/src/api/*`（V1 现有 66 个学生端接口）× V4 已上线/规划功能面
> 结论先行：**V4 的 11 个已建页面所需接口 V1 全部具备，零缺口；缺口全部集中在"新范式"功能**——
> AI 对话资产化（历史/推荐问题/场景）、圈子内容分栏、互动通知聚合、发布半屏的推荐位。
> 共 **6 组 / 14 个待补接口**，按优先级排列；均给出建议的请求/响应结构（字段与 V1 命名风格一致）。

---

## P0 · AI 学伴（核心差异化，阻塞沉浸式对话体验）

### 1. `GET /ai/history` — AI 对话历史列表
V1 的 `aiChat` 是无状态单次调用，V4 学伴页是**持续对话**，需要历史支撑（"🕘 上次：…"胶囊）。

```
响应 AiConversationVO[]:
  id          number        会话 id
  title       string        首条用户消息摘要（≤20 字，前端展示"上次：数据结构复习计划"）
  scene       string|null   发起场景（plan/paper/quiz/digest/checkin/course/free）
  updateTime  string        最近活跃时间（ISO）
  messageCount number
```

### 2. `GET /ai/history/{id}/messages` — 某会话消息明细
```
响应 ChatMessage[]（复用 V1 types/ai.ChatMessage）+ 每条可附 citations?: AiCitation[]
```

### 3. `POST /ai/history` — 落库当前对话
学伴页每次用户发言后调用（或会话结束时）。`data: { scene, messages }`。
> 备选：后端在 `aiRagChat` 内自动落库并返回 `conversationId`，前端免单独调用——二选一，建议后者。

### 4. `GET /ai/hot-questions` — 今日热问（学伴冷启动）
学伴页空态"今天大家都在问"3 条 + 底部 6 枚快捷胶囊的数据源。
```
响应 AiHotQuestionVO[]:
  question    string   完整问题（点击即发送）
  scene       string   路由场景
  heat        number   热度（排序用）
```

## P1 · 圈子详情（三分栏）

### 5. `GET /spaces/{id}/resources` — 圈内资料列表
V1 只有 `getSpacePosts`；V4 圈子详情有 动态/资料/打卡 三栏，资料栏无接口。
```
响应 ResourceVO[]（复用现有类型，带分页游标）
```

### 6. `GET /spaces/{id}/challenges` — 圈内打卡挑战列表
打卡栏无接口。`响应 CheckinChallengeVO[]（复用现有类型）`

---

## P1 · 消息中心（互动聚合）

### 7. `GET /notifications/interactions` — 互动通知聚合（按类型分栏）
V1 `getNotifications` 是平铺列表；V4 消息页是**赞/评论/关注三分栏 + 数字角标**。
```
请求: ?type=like|comment|follow&cursor=
响应 InteractionVO[]:
  type        'like'|'comment'|'follow'
  actor       { id, nickname, avatar }   操作者
  targetType  'post'|'resource'|'comment'  被动对象类型
  targetId    number
  targetTitle string                      「周五晚霞收容所」
  snippet     string                      评论内容 / 关注理由
  thumb       { kind:'image'|'pdf'|..., url? }  右侧缩略
  createTime  string
  unread      boolean
```
> 若后端倾向复用现有 `/notifications`，可仅补 `type` 过滤参数 + `actor`/`thumb` 字段扩展。

### 8. `POST /notifications/interactions/read` — 分栏批量已读
`data: { type }` 置某分栏全部已读（V1 只有全局 markAll）。

---

## P2 · 发布（半屏面板）

### 9. `GET /publish/recent-context` — 发布上下文推荐
半屏"发动态"的默认圈子、话题推荐（V4 面板文案承诺"选圈子同步/自动归入课程"）。
```
响应: { recentSpaces: SpaceVO[], hotTopics: string[], suggestCourse?: string }
```

### 10. `POST /ai/prefill` — 发布表单 AI 预填（可选增强）
"提问题"时由 AI 生成默认标签/悬赏建议。可复用 `aiRecommendTags`，无需新端点——**列为确认项**。

---

## P3 · 个人页（锦上添花）

### 11. `GET /users/me/checkin-heatmap?year=2026` — 年度打卡热力图
V4 个人页 365 格热力图。**可由前端用现有 `getRecords` 拉全年打卡记录自行聚合**——列为"可免补"项；仅当记录量大时后端出聚合接口：
```
响应: { days: [{ date:'2026-10-24', level:0|1|2|3|4 }], streak: 4, total: 132 }
```

### 12. `GET /users/me/drafts` / `POST /users/me/drafts` — 草稿箱
个人页"草稿箱"入口。`GET 列表 / POST 保存或删除`。

### 13. `PATCH /users/me/avatar` — 换头像
`data/me.js` 已留 `avatarUrl` 接口；需要上传（cos 直传或 base64）+ 更新接口。

### 14. `GET /circles/recommend?limit=8` — 全部圈子页排序优化（可选）
现有 `getSpaces` 可用；仅当要做"换一批/热度排序"时补 `sort=heat` 参数。
